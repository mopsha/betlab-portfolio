# ios/

**Folders (Nov 4, `docs/OVERHAUL.md`):** `BetLab/` is grouped by feature: `App`, `Core` (store, client, models, math), `Design` (theme, shared rows), `Today`, `Live`, `Build`, `Games`, `Promos`, `Friends`, `Me`. The project uses synchronized folders, so moving a file needs no project edit.

**The overhaul (Nov 4, `docs/OVERHAUL.md`):** tabs are Today, Live, Build, Games, Me. Screens draw from one kit: `Design/Kit.swift` (`GlowCard`, `RingArt`, `SectionTitle`, `HeroNumber`, `ArtStack`, `LivePill`, `Spark`), `Design/KitLive.swift` (score heads, leg rings) and `Design/KitMe.swift` (tiles, rows, faces, logos). Today leads with the day's units and one card per game with your bets on it; Live is Open and Settled only; Record, Stats, Ladder and Prices are screens under Me (`Me/BetScreens.swift`); Me has the units hero, tiles, and Extras for the rarely used screens. Friends is a feed, Ask BetLab a finished chat, Promos are token cards with a three-step finder, and Ladder shows the climb (Nov 4; kits `Design/KitSocial.swift`, `KitWallet.swift`). Build is three layers (header, modes, sport and game) then market tabs, with the promo and every book's price in the slip; Me is your number, four stats, Your betting, Badges, Friends, BetLab, Extras (Nov 4; `Design/KitBuild.swift`, `KitProfile.swift`). Rows below that describe the old Home, My bets and More layouts predate this.

The native iPhone app (SwiftUI, iOS 18+), started Oct 14. It reads the same Supabase database as the
web app, as the signed-in user, so row-level security applies. It's built on the Mac (Xcode 26.6), in the
same Claude session that changes the web app and the worker (one session since Oct 25): a change to one app is ported
to the other in that session.

No third-party packages: Supabase Auth and the REST API are called directly with URLSession.

## Build, test, run (on the Mac)

```
sh ios/scripts/make_secrets.sh
cd ios
xcodebuild -project BetLab.xcodeproj -scheme BetLab -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath build test
```

The app lands in `ios/build/Build/Products/Debug-iphonesimulator/BetLab.app` (git-ignored); Claude installs it on the
simulator and checks screenshots in **demo mode** (Nov 6, `Core/Demo.swift`): `xcrun simctl launch booted com.mopsha.betlab
-demo <fixture.json>` reads every table from a web preview fixture (`python scripts/sample_fixture.py` writes one; sample bets
go in its `my_bets`, a function's answer under its name), signs in as a made-up user that is never saved, and writes nothing,
so a check never touches a real account. Other hooks: `-tab bets|more|games`, `-openGame <game_id>`, `-appearance <theme id>`,
`-demoActivity YES` (with `-demo`, so its token goes nowhere). Signing uses Mike's paid Apple Developer team (`DEVELOPMENT_TEAM` YOUR_TEAM_ID, the same id as his old personal team; paid since
Oct 14), so installs last a year. `Config/BetLab.entitlements` turns on push notifications (`aps-environment`). A device build:
`xcodebuild ... -destination 'generic/platform=iOS' -allowProvisioningUpdates build`.

## Install on Mike's iPhone

With the iPhone plugged into the Mac (Developer Mode on):

```
xcodebuild -project BetLab.xcodeproj -scheme BetLab -destination 'id=<iPhone UDID>' -derivedDataPath build -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
xcrun devicectl device install app --device <device id from `xcrun devicectl list devices`> build/Build/Products/Debug-iphoneos/BetLab.app
```

First install (Oct 14): the phone said "Unable to Verify App ... An Internet connection is required" on Wi-Fi and cellular
alike. The development certificate was minutes old; a full iPhone restart (and a short wait) fixed it. The app and the
home-screen web app share the name and icon: the installed one is under App Library > Recently Added.

## TestFlight

`sh ios/scripts/testflight.sh` archives a Release build (production push: `apns:production:` tokens), signs it for the App
Store with the Apple ID in Xcode and uploads it; the build number is the git commit count. App Store Connect's app record:
bundle id `com.mopsha.betlab`. Internal testing (Mike) needs no review. `ITSAppUsesNonExemptEncryption` is false (HTTPS only).
The APNs key must be for **Sandbox & Production**: the first key was Sandbox only, and Apple refused every TestFlight alert
with `403 BadEnvironmentKeyInToken` (Oct 14; Mike made a new key and replaced APNS_KEY_P8 / APNS_KEY_ID in Railway).
A new capability or bundle id needs Apple's account, not the API key: the widget extension's App Group
(`group.com.mopsha.betlab`) and `com.mopsha.betlab.widgets` failed at signing with "Authentication failed" from the key
(Oct 27). Mike signs in once in Xcode > Settings > Accounts (or registers them on developer.apple.com); after that the
script signs as before.

## Testing hook

`xcrun simctl launch booted com.mopsha.betlab -openGame <game_id> -expandFolds YES` opens the app on that game's page with
every analysis section open, for checking screenshots without tapping through. `-tab build -betlab-build-promo bonus` (or `boost:50`, `none`) opens Build with that promo. Launch arguments last for that launch only.
